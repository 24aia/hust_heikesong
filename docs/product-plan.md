# 产品计划书

## 核心场景

用户在知乎阅读长回答或专栏文章，中途被打断。重新打开页面后，问题有两个：找不回上次读到哪一段，以及忘了前文讲过什么。

本产品是一个桌面版火狐扩展，在支持的知乎页面右下角提供一个阅读伙伴：

1. 本地记录停留位置，也支持手动标记"记住这里"。
2. 重新打开页面时提示续读，确认后滚动回原段落并短暂高亮。
3. 可选回顾断点之前的要点，并从引用跳回原文继续阅读。

自动断点与手动书签是两份独立记录，自动记录永不覆盖手动书签。

## AI 的作用

AI 只用于一件事：把用户已经读过的前文压缩成 3–5 个要点或一段衔接说明，帮助接回思路。

边界是明确的：

- 只发送用户选定断点**之前**的正文，断点段落及后文不进入请求。
- 不联网补全文章内容，不用模型的外部知识充当原文证据。
- 每个要点必须附带段落 ID 和在该段落中逐字存在的引用；后端逐条校验，校验失败不显示。
- 记录阅读位置的过程完全不调用 AI，只有用户明确点击才发起请求。

模型走知乎直答 `zhida-fast-1p5`。

## 模块方案

| 模块 | 位置 | 职责 |
|---|---|---|
| 扩展宿主 | `apps/extension` | 页面适配、正文提取、断点记录与恢复、本地存储 |
| 回顾面板 | `packages/recap-ui` | brief/bridge 两种回顾模式、引用交互、缓存 |
| 总结后端 | `apps/recap-api` | 异步任务队列、直答适配、输出与引用校验 |
| 数据契约 | `contracts` | 唯一协议源：类型、JSON Schema、哈希规则、黄金样例 |

扩展与后端解耦：后端不可达时，记录与恢复照常工作。面板不访问知乎 DOM，只通过 `ReadingHost` 接口请求前文、定位引用和继续阅读。

数据全部存在扩展本地 `storage.local`，不写宿主页面，不做跨设备同步。

## 实际验证

已实际执行并通过：

- 契约校验：6 个 fixture 与两端哈希一致。
- 单元测试：7 个文件、26 个测试，覆盖定位算法（重复段落、自然省略号、emoji 长段、动态正文追加、节流窗口不丢候选）、迟到结果隔离、超长输入返回 `INPUT_TOO_LARGE`。
- `web-ext lint`：0 errors，火狐 manifest 结构有效（Mozilla 官方 addons-linter，与 AMO 签名同一套校验）。
- 后端 Mock 验收：任务凭证隔离、服务端重算哈希、引用逐字校验、重启标记 `JOB_INTERRUPTED`。
- 真实知乎直答验收：`zhida-fast-1p5` 返回 3 个要点，可按 `RecapResult v1` 解析，引用全部逐字命中，约 16 秒完成（单次小样本，不代表稳定延迟）。

## 已知限制

诚实记录，不夸大：

- **扩展在火狐真实知乎页面上的注入与恢复尚未人工验证。** 目前只验证了火狐能载入扩展。
- **回顾功能未公开部署。** 交付的 `.xpi` 不含可用的公开后端，该功能通过演示视频展示，评委如需自行体验须按 `apps/recap-api/README.md` 自建本地后端。这样做是因为公开端点会让本项目的知乎凭证替所有访问者付费，且限速与配额策略尚未实测。
- 支持范围只有单回答详情页与专栏文章页；问题下的多回答聚合页未适配。
- 不支持手机版火狐，不支持 Chrome 与 Edge。
- 不绕过登录、付费或内容访问限制；正文能否读取以实际页面为准。
- 第一版不处理图片中的文字与公式，存在关键非文本内容时给出 warnings。
- 阅读进度只称"位置估计"，不声称用户已读懂或读完。
- 尚未完成 5 篇长文、10 个断点的人工实测，因此不提供成功率数字。
- 当前 mascot 是原创临时图标，不是知乎官方刘看山素材。
- 卸载扩展会丢失本地断点。
